# Copilot Instructions for SharingBeer Project
- usa la lingua italiana nelle risposte
## Project Overview
SharingBeer is a Node.js web application for beer sharing and delivery management. It's built with Express.js and uses Nunjucks for templating.

## Tech Stack
- **Backend**: Node.js con Express.js
- **Database**: MongoDB con Mongoose ODM
- **Templating**: Nunjucks (.njk files) per rendering server-side
- **Autenticazione**: Passport.js con strategia locale
- **Pagamenti**: Axerve/GestPay (principale) e PayPal (secondario)
- **Email**: Nodemailer per notifiche automatiche
- **Frontend**: HTML5, CSS3, JavaScript vanilla con Bootstrap
- **Mappe**: Integrazione servizi di geolocalizzazione
- **QR Code**: Generazione dinamica per ordini/inviti
- **Session**: Express-session per gestione stato utente
- **Crittografia**: bcrypt-nodejs per password hashing
- **Deployment**: Docker con Fly.io (staging e produzione)

## Project Structure
- `server.js` - Entry point principale dell'applicazione
- `app/` - Logica core dell'applicazione
  - `routes*.js` - Handler per diverse funzionalità (Auth, Shop, Delivery, Dashboard, etc.)
  - `models/` - Modelli database (User, Product, Brewery, etc.)
  - `controllers/` - Logica di business
  - `middleware/` - Middleware personalizzati
  - `libfunction.js` - Funzioni di utilità comuni
  - `axerveResposeManagement.js` - Gestione risposte pagamenti Axerve
  - `overpassQuery.js` - Query per servizi di mappe
  - `gestpay_service/` - Servizi integrazione GestPay
  - `wscryptdecrypt/` - Crittografia per comunicazioni sicure
- `views/` - Template Nunjucks per rendering HTML
- `public/` - Asset statici (CSS, JS, immagini, audio)
- `config/` - File di configurazione (database, email, passport)
- `data/` - Dati di reference (comuni italiani, vCard)
- `uploads/` - File caricati dinamicamente (QR codes, immagini)

## Key Features
- **Sistema di inviti**: Registrazione solo tramite invito (dal birrificio o da utenti esistenti)
- **Gestione prodotti birra**: Catalogo con caratteristiche tecniche dettagliate (EBC, IBU, grado Plato, allergeni)
- **Sistema BeerBox**: Vendita in confezioni da 6 bottiglie (500ml), non vendita singole bottiglie
- **Carrello avanzato**: Gestione multipla beerbox con controllo stock in tempo reale
- **Compositore BeerBox**: Creazione beerbox personalizzati con mix di birre
- **Gestione magazzino**: Controllo automatico disponibilità e stock beerbox/bottiglie
- **Sistema consegne**: Ritiro in birrificio o consegna a domicilio con gestione geografica
- **Gestione ordini**: Stati complessi (OK, consegnato, ritirato) con tracking
- **Sistema punti**: Accumulo "booze points" e birre omaggio per inviti
- **Pagamenti**: Integrazione Axerve/GestPay e PayPal
- **QR Code**: Generazione per ordini e inviti amici
- **Notifiche email**: Sistema completo per ordini, inviti, conferme
- **Geolocalizzazione**: Integrazione mappe per consegne e calcolo distanze
- **Sistema amicizie**: Inviti, tracking e rewards per referral

## Logica Business Specifica

### Sistema BeerBox
- **Unità vendita**: Solo beerbox da 6 bottiglie (500ml)
- **Variabile globale**: `numBottigliePerBeerBox = 6`
- **Stock management**: Controllo disponibilità in tempo reale
- **Limite spedizioni**: Massimo beerbox per spedizione (array `priceCurier`)

### Gestione Carrello
- **Struttura**: `req.session.newcart[beerboxId][productId]`
- **ID BeerBox**: Generato con `lib.generateToken(10)`
- **Controlli concorrenza**: Verifica stock durante composizione
- **Multiplier**: Campo `moltiplica` per incrementi/decrementi

### Sistema Inviti e Rewards
- **Booze Points**: Accumulati tramite inviti e acquisti referral
- **Calcolo**: `booze4Parent = ((totalPriceBeer / (totalQty * numBottigliePerBeerBox)) / numAcquistiPerUnaBottigliaOmaggio) * totalQty`
- **Birre omaggio**: Sistema automatico per primi acquisti

### Gestione Consegne
- **Ritiro**: Birrificio Viana (via Molignati 12, Candelo BI)
- **Consegna**: Gestione geografica con integrazione mappe
- **Spedizione**: Servizio corriere con limiti quantità
- **Stati**: OK, consegnato, ritirato, spedito

### Sistema Pagamenti
- **Primario**: Axerve/GestPay con gestione S2S
- **Secondario**: PayPal
- **Gestione**: `axerveResposeManagement.js` per callback
- **Security**: Crittografia tramite `wscryptdecrypt`

## Pattern di Codice Comuni

### Struttura Route Handler
```javascript
app.get('/route', lib.isLoggedIn, async (req, res) => {
  try {
    // Controllo autenticazione tramite middleware lib.isLoggedIn
    lib.newRetriveCart(req); // Aggiorna carrello in sessione
    
    // Logica business specifica
    const data = await Model.aggregate([...]);
    
    res.render('template.njk', { 
      user: req.user,
      data: data,
      numBottigliePerBeerBox: numBottigliePerBeerBox 
    });
  } catch (error) {
    console.error('Errore in route:', error);
    req.flash('error', 'Errore interno del server');
    res.redirect('/dashboard');
  }
});
```

### Gestione Carrello Pattern
```javascript
// Inizializzazione carrello
const cart = req.session.newcart || {};
const idBBX = lib.generateToken(10);

// Controllo stock prima aggiunta
const prod = await Product.findById(id);
if (prod.quantity < quantityRequired) {
  req.flash('info', 'Stock insufficiente per ' + prod.name);
  return res.redirect('/shop');
}

// Aggiunta al carrello
cart[idBBX][id] = {
  id: prod._id.toString(),
  name: prod.name,
  quantity: quantityToAdd,
  price: prod.price.toFixed(2),
  qty: (quantityToAdd / numBottigliePerBeerBox),
  moltiplica: 1
};
```

### Aggregation MongoDB Pattern
```javascript
const ordini = await User.aggregate([
  { $match: { "_id": req.user._id } },
  { $unwind: "$orders" },
  { $match: { 
    $and: [
      { "orders.status": "OK" },
      { "orders.typeShipping": "consegna" }
    ]
  }},
  { $sort: { "orders.deliveryDate": -1 } }
]);
```

## Convenzioni UI (Navbar, Invita, Carrello)

### Evidenziazione “Invita” (amiciDaInvitare)
- Stato calcolato server-side e reso disponibile in ogni request: `res.locals.amiciDaInvitare`.
- Applicazione classi direttamente in template `views/layouts/main.njk`:
  - `<div id="invita" class="{%- if amiciDaInvitare %}invita_div{%- endif %}">`
  - `<span id="imgInvita" class="material-symbols-outlined {%- if amiciDaInvitare %}pulsa{%- endif %}">`
- Non usare JS per togglare classi su “Invita” (evita flicker e dipendenze da timing). Se cambia la logica:
  - aggiornare l’assegnazione di `res.locals.amiciDaInvitare` in `server.js` e in `lib.isLoggedIn` (dopo ricalcolo nel flusso protetto).

### Badge Carrello (lblCartCount)
- Il badge del carrello non deve essere visualizzato quando il carrello è vuoto.
- Rendering server-side in `main.njk`:
  - renderizzare `<span id="lblCartCount" class="badge badge-warning">` solo se `user` è presente e `numProducts > 0`.
- Aggiornamenti client-side (shop/composer):
  - Gli script devono gestire l’assenza iniziale del badge creando dinamicamente il nodo quando si passa da 0 a >0.
  - Contenitore badge: elemento con id "carrello" (stesso elemento che contiene l’icona Shopping_Cart).
  - ID badge: elemento con id "lblCartCount".
  - Composer incrementa di `res.ntb/6`; Shop incrementa di `+1` per beerbox.
  - Se il conteggio dovesse tornare a 0 con logiche client, rimuovere il nodo badge per coerenza visiva.

### Preferenze di rendering
- Prediligere sempre il rendering server-side dello stato UI per elementi persistenti (es. inviti, badge non numerico) e usare JS solo per aggiornamenti incrementali post-azione.
